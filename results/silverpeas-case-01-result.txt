Matched comparison
------------------

The critical matched order is:

B -> A

Clean-state protocol:
deployments/ absent before B
B -> FAIL

Reused-state protocol:
deployments/ present before B
B -> PASS

The order is identical. The difference is whether filesystem state created by
the preceding A -> B execution is reset or preserved.

Manual causal validation
------------------------

B executed alone with deployments/ absent:
FAIL

A executed in a separate Gradle/JVM invocation:
PASS and creates deployments/

B executed in another separate Gradle/JVM invocation without reset:
PASS

Therefore the relevant state survives across execution/JVM boundaries.

Interpretation
--------------

This real IDoFT case demonstrates that cross-execution persistent filesystem
state can mask an order-dependent brittle-test failure.

Under clean state, the B -> A order exposes the brittle behavior because B
starts without the required deployments/ directory.

Under reused state, the same B -> A order no longer exposes the failure because
the directory created during the previous A -> B execution persists on disk.

Thus persistent state changes the observed OD behavior even though the test
orders are identical.

Scope
-----

This result establishes the persistent-state effect for this Silverpeas case.

It does not establish prevalence across IDoFT and it is not yet an iDFlakies
detection result.
