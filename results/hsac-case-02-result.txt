Tests:

Persistent filesystem resource:
src/test/resources/temp-copy.txt

Matched execution sequence under both protocols:
01: A
02: B

CLEAN PROTOCOL

A:
- state before: ABSENT
- result: PASS
- state after: PRESENT

B:
- temp-copy.txt is reset before execution
- state before: ABSENT
- result: FAIL
- failure reason: testDelete cannot find temp-copy.txt
- state after: ABSENT

REUSED PROTOCOL

A:
- state before: ABSENT
- result: PASS
- state after: PRESENT

B:
- no reset is performed between A and B
- state before: PRESENT
- result: PASS
- state after: ABSENT because testDelete consumes the file by deleting it

RESULT

The exact same A -> B execution sequence was used under clean and reused
protocols.

Clean:
  A: ABSENT  -> PASS -> PRESENT
  B: ABSENT  -> FAIL -> ABSENT

Reused:
  A: ABSENT  -> PASS -> PRESENT
  B: PRESENT -> PASS -> ABSENT

The difference in B's result is caused by cross-execution filesystem state.
A creates temp-copy.txt in one Maven execution. Under the reused protocol,
that file remains available to B in the following separate Maven execution,
so B passes. Under the clean protocol, the file is removed before B, so B
fails.

This establishes that, for this real IDoFT case, persistent filesystem state
across separate test executions changes the observed outcome of the brittle
test under an otherwise identical execution sequence.

This result demonstrates consequence for this case; it does not establish
prevalence across IDoFT.

This matched experiment measures test outcome sensitivity to persistent state.
It does not yet measure iDFlakies detector reporting for this HSAC case.
