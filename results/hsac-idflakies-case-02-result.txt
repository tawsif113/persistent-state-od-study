PROTOCOL VALIDATION

The reused-state mechanism did preserve cross-JVM filesystem state when that
state survived an execution.

During a later verification execution, the reused trace records:

ORDER_START_PRE_RESET=true
ORDER_START_POST_RESET=true

At the corresponding clean execution, the trace records:

ORDER_START_PRE_RESET=true
ORDER_START_POST_RESET=false

Therefore the absence of a detector difference is not caused by failure of
the reused-state protocol.

The reason differs from the Silverpeas case.

In HSAC, testDelete consumes the relevant persistent state when it succeeds:
testCopyTo creates temp-copy.txt and testDelete deletes it. Therefore the
original A -> B execution leaves temp-copy.txt absent. The subsequent
revealing/reverse execution consequently begins with the relevant state absent
under both clean and reused protocols.

Persistent-state outcome sensitivity and detector-reporting sensitivity are
therefore distinct in this case.

The separately matched HSAC experiment established that cross-execution
filesystem persistence can change testDelete's outcome when A and B execute in
separate executions without B first consuming the state.

This iDFlakies experiment establishes that the same persistent-state mechanism
does not alter reverse-detector reporting when the detector's original A -> B
execution consumes that state before the next detector execution.

This is a contrast case demonstrating that the effect of persistent state on
OD detection depends on the lifetime of the state relative to the detector's
execution schedule. It does not establish prevalence across IDoFT.
