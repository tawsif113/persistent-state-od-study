Clean-state protocol:
Delete build/resources/test/deployments before every order execution.

Reused-state protocol:
Delete build/resources/test/deployments once before the protocol begins,
then preserve it across all subsequent test and order executions.

Execution-unit note:
Each test element is executed using a separate Gradle --no-daemon invocation.
Therefore JVM/process state cannot carry from one test execution to the next.
Filesystem state can carry unless explicitly reset.

Purpose:
Determine whether identical A/B order sequences produce different B outcomes
when cross-execution filesystem state is reset versus reused.

This matched causal experiment is separate from the later iDFlakies detector
experiment.
